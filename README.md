# Автотесты для сайта DemoQA | VolgaIT 2026

Python 3.12+, Pytest, Selenium, Requests и Allure. Негативные проверки добавлены
по пунктам 3–6 задания: книги в профиле, каталог и UI-поиск. Набор использует
существующие Page Object и API-клиент проекта.

## Запуск

Нужны Python 3.12+ и установленный Chrome/Chromium. Selenium Manager подберёт
драйвер; для первого запуска нужен доступ к сервису загрузки драйверов.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Запуск тестов:
```bash
python -m pytest
```

Параллельный запуск:

```bash
python -m pytest -m negative -n 2 --headless
```

Последняя команда также запускает существующие негативные тесты авторизации.
Для окна браузера уберите `--headless`. Путь к Chromium можно передать через
`--browser-binary=/usr/bin/chromium`. В изолированном CI-контейнере при
необходимости используется `--no-sandbox`; по умолчанию песочница включена.
При работе через HTTP-прокси доступен параметр `--browser-proxy=адрес`.
Корневой сертификат такого прокси должен быть доверенным в браузере.

## Сценарии API

Каждая новая негативная API-проверка сравнивает статус и весь JSON ошибки
(`code`, `message`). Затем авторизованный запрос проверяет исходный состав
коллекции, включая число книг и ISBN.

| ID Allure | Действие | Ожидаемый ответ |
| --- | --- | --- |
| API-BOOKS-NEG-01, 2 варианта | Получить профиль без токена или с некорректным токеном | `401`, `1200`, `User not authorized!` |
| API-BOOKS-NEG-02 | Повторно добавить одну книгу, уже находящуюся в профиле | `400`, `1210`, `ISBN already present in the User's Collection!` |
| API-BOOKS-NEG-03 | Добавить несуществующий ISBN `0000000000000` | `400`, `1205`, `ISBN supplied is not available in Books Collection!` |
| API-BOOKS-NEG-04 | Удалить существующую книгу, которой нет в профиле | `400`, `1206`, `ISBN supplied is not available in User's Collection!` |
| API-BOOKS-NEG-05, 2 варианта | Без токена удалить одну книгу или все книги | `401`, `1200`, `User not authorized!` |
| API-BOOKS-NEG-06 | Без токена добавить пакет из двух книг | `401`, `1200`, `User not authorized!` |

Итого: 8 новых API-проверок с учётом параметров. В `tests/test_api.py` дополнены
существующие проверки несуществующего ISBN и добавления одной книги без токена;
у негативных API-тестов проставлены маркеры `api` и `negative`.

Список магазина публичный: отсутствие токена у `GET /BookStore/v1/Books`
не является ошибкой. Негативное получение данных книги проверяет существующий
тест `API-NEG-01` с несуществующим ISBN; отсутствие результатов в каталоге
проверяется UI-поиском.

На проверенном DemoQA пакет уже добавленных ISBN возвращает `201` и сохраняет
исходный состав коллекции. Ожидание `400` для такого пакета не заложено:
пакетный негативный сценарий проверяет отсутствие авторизации.

## Данные и отчёт

Тесты создают уникального пользователя через API для каждого сценария и удаляют
его после завершения. Для проверки изменения коллекции добавляются две книги
из актуального каталога. После UI-входа API-клиент получает токен текущей
браузерной сессии. При очистке предусмотрено обновление токена, если UI-вход
заменил прежний. Новые тесты не используют общий аккаунт из `DemoQAUser`.

Ожидания используют Selenium WebDriverWait. В Allure записываются названия
сценариев и шаги; при падении UI-теста прикладывается скриншот Selenium.
Результаты по умолчанию сохраняются в `allure-results`.

Если установлен Allure CLI:

```bash
allure serve allure-results
```

Этот README описывает доработанный негативный набор. Остальные пункты финального
задания, включая новые позитивные сценарии, E2E и другие браузеры, требуют
отдельной работы.

## Результат проверки доработки

11 ноября 2026 года: 13 негативных API-проверок прошли при запуске в два
процесса; 12 негативных UI-проверок прошли в Chromium 156. Дополнительно прошли
два существующих UI-теста: поиск книги и добавление книги через интерфейс.
Синтаксис Python и `git diff --check` проверены.

API проверялся напрямую на `https://demoqa.com`. Для UI в рабочей облачной
среде использовался временный локальный прокси до того же DemoQA, поскольку
Chrome не доверял сертификату прокси среды. TLS до DemoQA проверялся стандартным
хранилищем CA среды. Страницы, API-ответы и данные сайта не подменялись; браузер
открывал локальный адрес.
